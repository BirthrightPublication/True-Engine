# TRUE ENGINE 0.1.3 — embeddable browser SDK

This approved integration patch extends the existing engine; it does not start an unrelated roadmap phase. Native Rust SDK contract 0.1 and project schema 1 remain compatible with 0.1.0–0.1.2. No existing installation, project, settings, earlier source tag or release package is replaced by building the SDK.

New reusable package: `@birthright/true-engine@0.1.3`, distributed as `True-Engine-SDK-v0.1.3-web.zip` plus `.zip.sha256`. It includes actual compiled Rust/wgpu WebAssembly, browser ES modules, declarations, compatibility and per-file checksum manifests, dependency notices, public API/Windows build documentation and a working host-owned canvas example. No CSS renderer, mock engine, npm registry publication or application-specific plate logic is included. Original-code licensing remains the owner's decision.

Implemented API: async canvas initialization with WebGPU/WebGL2 selection, cube/plane/sphere and validated indexed triangle meshes, opaque color materials and flat diffuse lighting, hierarchical TRS, perspective orbit/pan/zoom/reset, picking, resize, event-driven frames, validated browser document save/reopen, explicit disposal. Custom meshes remain external to native schema 1. Browser documents use a separate `true-engine-web-project` format/version 1 envelope that carries native scene, meshes and camera; native readers do not accept that envelope as a native project. Importing a native schema 1 file remains supported. No automatic migration or persistent-data write occurs.

A narrow generated-JavaScript bridge omits the retired `maxInterStageShaderComponents` device limit only where the browser no longer exposes it. It preserves every active limit and calls the actual GPU adapter; browser prototypes are unchanged. The build fails if the pinned generated request-device stub changes. Browser GPU resources retain their adapter/instance handles and are explicitly destroyed/unconfigured at disposal.

Changed source areas: `crates/true-engine/{geometry,scene,render}` additive external-mesh APIs; new `crates/true-engine-web`; `sdk/web`; `examples/browser-sdk`; custom mesh/document/GPU/browser tests; `tools/sdk`; release workflow/native test commands; SDK/consumer architecture/build/compatibility docs, engineering directives, Cargo version/lock and ignore rules. Exact changed paths are in the tagged Git diff and package manifest.

Tests actually executed and remaining limits are recorded in docs/SDK_VALIDATION-0.1.3.md and each package manifest's test evidence. Linux tests do not establish Windows runtime compatibility. GitHub native Windows build/updater/browser results must be independently observed; interactive Windows hardware/GPU compatibility remains separate. No PBR, textures, transparency, glTF parser, orthographic camera, gizmos, simulation framework or production qualification is claimed.

Plate Studio recommendation: vendor the exact versioned `package/` files and verify the release ZIP digest, then import `createViewport` from its pinned ES-module path. Its inspected main source currently has CSS-only preview and an HTTP/PyInstaller asset allowlist that must be expanded to serve/package the actual SDK `.js`/`.wasm` files and MIME types. This release delivers a tested engine-owned example; it does not claim Plate Studio itself has been integrated or change its repository. See docs/PLATE_STUDIO_INTEGRATION.md.

Standard Windows application/updater assets remain `True-Engine-v0.1.3-windows-x64.zip` and checksum, with complete `app/` payload and data-preserving updater behavior. Those are separate from the browser SDK ZIP. The SDK does not need a Windows application installation or invoke its updater.
